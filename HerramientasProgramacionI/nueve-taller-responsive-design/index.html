📲 Mobile First y viewport

⏱️ 30 minutos · "Empieza por lo pequeño" — la base de todo responsive

🧠 La idea central

Antes de tocar la tabla o el menú, hay que poner dos cimientos: la etiqueta <meta name="viewport"> (para que el navegador use el ancho real del celular) y la estrategia Mobile First (diseñar primero para móvil y luego agrandar con min-width).

📲 Paso 1: la etiqueta viewport

Sin esta línea, el celular "finge" tener 980px y encoge todo. Es la primera línea que debes revisar.

index.html
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
</head>

📲 Paso 2: la escalera de Mobile First

PasoQué hacesEjemplo
1. Base móvilEstilos para celular (una columna).tarjeta { width: 100%; }
2. TabletCon @media, dos columnas@media (min-width: 768px)
3. EscritorioCon @media, tres o más columnas@media (min-width: 1024px)

💡 Pro-Tip

En Mobile First usas min-width: "a partir de este ancho, aplica esto". Empiezas simple y vas sumando. Es lo contrario de max-width, que dice "hasta este ancho, aplica esto" (el enfoque antiguo de escritorio primero).

🃏 Tabla → cards

⏱️ 35 minutos · "El reto fuerte" — convertir la tabla de autores en cards apiladas

🧠 La idea central

Una tabla de 4 columnas no cabe en un celular. La solución clásica es convertir cada fila en una card: en pantallas angostas, cada autor se muestra como una tarjeta apilada con su información en vertical. Esto se logra con una media query y la propiedad display.

🃏 La técnica: de fila a card

Con @media (max-width: 600px) cambiamos el display de la tabla: cada <tr> se vuelve un bloque y cada <td> se apila. El truco del data-label pone la etiqueta delante de cada valor.

estilos.css
/* En pantallas angostas, la tabla se vuelve cards */
@media (max-width: 600px) {
  .tabla thead { display: none; }          /* ocultamos la fila de títulos */

  .tabla, .tabla tbody, .tabla tr, .tabla td {
    display: block;                        /* todo se apila en vertical */
    width: 100%;
  }

  .tabla tr {
    border: 1px solid #cbd5e1;
    border-radius: 8px;
    margin-bottom: 0.6rem;
    padding: 0.4rem;
  }

  .tabla td {
    border: none;
    display: flex;
    justify-content: space-between;
  }

  /* la etiqueta sale del atributo data-label */
  .tabla td::before {
    content: attr(data-label);
    font-weight: 700;
  }
}

⚠️ El atributo data-label

Para que cada card muestre "Nombre", "País", etc., cada <td> lleva un atributo data-label con el nombre de su columna. El CSS lo lee con content: attr(data-label). Sin ese atributo, la card solo mostraría los valores sin saber qué es cada uno.

📏 Menú adaptable

⏱️ 30 minutos · "El reto suave" — el menú se encoge, no se esconde

🧠 La idea central

Con solo tres items, el menú no necesita convertirse en hamburguesa: basta con reducir los tamaños proporcionalmente usando unidades relativas (rem, %) y una media query. Es la forma más simple y limpia de hacerlo responsive, y refuerza la idea de Mobile First.

📏 La técnica: encoger, no esconder

En la base móvil el menú es compacto; en escritorio crece con más aire. Todo con rem y gap.

estilos.css
/* base móvil: menú compacto, en fila */
.menu-lista {
  display: flex;
  gap: 0.5rem;
  font-size: 0.9rem;
}
.menu-lista a { padding: 0.4rem 0.7rem; }

/* escritorio: crece con más aire */
@media (min-width: 768px) {
  .menu-lista { gap: 1.5rem; font-size: 1.1rem; }
  .menu-lista a { padding: 0.6rem 1.2rem; }
}

❌ Menú hamburguesa

Esconde los items detrás de un botón ☰. Útil con muchos items, pero requiere JavaScript o trucos de CSS avanzados que aún no vemos.

✅ Menú adaptable

Con 3 items, basta encogerlos con unidades relativas. Sin JavaScript, sin trucos: solo CSS y una media query.

💡 Pro-Tip: rem vs px

Si usas px fijos, el menú no se adapta. Con rem (relativo a la fuente raíz) y %, los tamaños escalan con el contexto. Por eso las unidades relativas son la base del responsive design.

⭐ Crea estilos.css y hazlo responsive ⏱️ 15 min · el paso más importante

Crea estilos.css con el CSS mínimo de escritorio y luego agrega las dos media queries: la de tabla→cards y la del menú adaptable.

clase09-taller/estilos.css
/* --- CSS mínimo de escritorio --- */
body { font-family: 'Segoe UI', sans-serif; margin: 0; color: #1a1a1a; }
header { background: #1e3a5f; color: #fff; padding: 1rem; }
.menu-lista { display: flex; gap: 1.5rem; list-style: none; padding: 0.6rem 1rem; }
.menu-lista a { text-decoration: none; color: #1e3a5f; font-weight: 600; }
main { padding: 1rem; }
.tabla { width: 100%; border-collapse: collapse; }
.tabla th, .tabla td { border: 1px solid #cbd5e1; padding: 0.5rem; text-align: left; }
.tabla th { background: #e2e8f0; }

/* --- MÓVIL: menú compacto --- */
.menu-lista { gap: 0.5rem; font-size: 0.9rem; }
.menu-lista a { padding: 0.4rem 0.7rem; }

/* --- MÓVIL: tabla → cards --- */
@media (max-width: 600px) {
  .tabla thead { display: none; }
  .tabla, .tabla tbody, .tabla tr, .tabla td { display: block; width: 100%; }
  .tabla tr { border: 1px solid #cbd5e1; border-radius: 8px; margin-bottom: 0.6rem; padding: 0.4rem; }
  .tabla td { border: none; display: flex; justify-content: space-between; }
  .tabla td::before { content: attr(data-label); font-weight: 700; }
}

/* --- ESCRITORIO: menú con más aire --- */
@media (min-width: 768px) {
  .menu-lista { gap: 1.5rem; font-size: 1.1rem; }
