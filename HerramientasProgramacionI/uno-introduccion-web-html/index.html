🌍 Internet y la web

⏱️ 35 minutos · "La red de redes" — quién habla con quién

🧠 La idea central

Internet es una red gigante de computadores conectados entre sí por cables, fibra óptica y señales inalámbricas. La web es una de las cosas que viajan por esa red: páginas, imágenes, videos.

En esa conversación hay dos protagonistas: el cliente (tu navegador, que pide) y el servidor (un computador lejano, que responde). El navegador es el programa que usas para ver la web: Chrome, Firefox, Edge.

🌐 Internet

La red física: cables, routers, servidores. Es la "carretera" por donde viaja la información.

🕸️ La Web

El contenido que viaja por Internet: páginas, sitios, videos. Es lo que "circula" por la carretera.

🧭 Navegador

El programa que usas para ver la web: Chrome, Firefox, Edge. Es tu "ventana" a Internet.

🧱 HTML, CSS y JavaScript

⏱️ 35 minutos · "Las 3 tecnologías de la web" — estructura, estilo y comportamiento

🧠 La idea central

Toda página web se construye con tres tecnologías que trabajan juntas. Como una casa: HTML son los muros (la estructura), CSS es la pintura (el estilo) y JavaScript es la electricidad (el comportamiento).

🏗️ HTML

Estructura. Define qué hay en la página: títulos, párrafos, enlaces, imágenes. Es el esqueleto.

🎨 CSS

Estilo. Colores, tamaños, márgenes. Hace que la página se vea bonita.

⚡ JavaScript

Comportamiento. Hace que los botones funcionen y la página responda.

📄 Estructura de una página HTML

⏱️ 35 minutos · "El esqueleto mínimo" — DOCTYPE, html, head y body

🧠 La idea central

Toda página HTML tiene un esqueleto mínimo que se repite siempre. Son cuatro piezas: la declaración <!DOCTYPE html>, la etiqueta <html>, la <head> (información invisible) y el <body> (lo que se ve).

🦴 Las 4 piezas del esqueleto

PiezaQué es¿Se ve?
<!DOCTYPE html>Le dice al navegador "esto es HTML moderno"No
<html>Envuelve toda la páginaNo
<head>Información: título, idioma, enlaces a estilosNo (salvo el título en la pestaña)
<body>Todo el contenido visibleSí

💻 El esqueleto mínimo

index.html
<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <title>Mi primera página</title>
</head>
<body>
  <h1>¡Hola, mundo!</h1>
  <p>Esta es mi primera página web.</p>
</body>
</html>

🎮 Simulador: Arma el esqueleto

⚠️ Error común: olvidar el <body>

Todo lo que quieras que se vea en la página debe ir dentro de <body>. Si lo pones en <head>, no se mostrará (o se mostrará mal). El <head> es solo para información "invisible".

🏷️ Etiquetas básicas

⏱️ 35 minutos · "h1-h6, p, a, br, hr" — las etiquetas que usarás siempre

🧠 La idea central

Las etiquetas son las palabras entre < > que le dicen al navegador qué mostrar. Hay decenas, pero estas cinco son las que usarás en casi toda página: encabezados (h1-h6), párrafos (p), enlaces (a), salto de línea (br) y línea horizontal (hr).

🏷️ Las 5 etiquetas esenciales

EtiquetaQué haceEjemplo
<h1> a <h6>Encabezados (h1 el más grande, h6 el más chico)<h1>Título</h1>
<p>Párrafo de texto<p>Hola</p>
<a>Enlace a otra página<a href="...">Ir</a>
<br>Salto de línea (no necesita cierre)Línea 1<br>Línea 2
<hr>Línea horizontal separadora<hr>

🛠️ Taller: publica tu página en Internet

⏱️ 35 minutos · Trabajo individual · GitHub + Codespaces + GitHub Pages

🎯 Tu misión

Tu página "Sobre mí" va a dejar de vivir escondida en un computador: hoy la vas a poner en Internet, con una dirección real que puedes abrir desde tu celular y mandarle a quien quieras.

Para eso vas a crear un repositorio en GitHub que usarás todo el año. Cada clase no empieza de cero: agrega una carpeta nueva al mismo repositorio. Al terminar el año, ese repositorio será tu portafolio.

6
Sube tus cambios (commit + push) ⏱️ 4 min · el paso que más se olvida

Mientras escribes, Codespaces trabaja sobre una copia. Para que GitHub —y el mundo— vea tu trabajo, hay que enviarlo:

  1. En la barra de la izquierda pulsa el icono Source Control (las ramitas, con un número azul que indica cuántos archivos cambiaron).
  2. En la caja de texto de arriba escribe el mensaje: Clase 1: página Sobre mí
  3. Pulsa Commit. Si pregunta si quieres preparar todos los cambios, responde Yes (o Always).
  4. Pulsa Sync Changes (o Push) para enviarlos a GitHub.
  5. Vuelve a la pestaña de tu repositorio, recarga y comprueba que aparecen clase01/ y tu index.html.

⚠️ Regla de oro

Si no hiciste commit + push, tu trabajo no existe para nadie más: no lo ve tu profesor/a, no lo ve GitHub Pages y no lo ve tu URL. Repite este paso cada vez que avances algo importante.

El mensaje de commit describe qué hiciste. Úsalo bien desde hoy: Clase 1: página Sobre mí ✅  ·  asdf ❌

7
Activa GitHub Pages ⏱️ 3 min · solo la primera vez

Este paso se hace en github.com (no en Codespaces) y solo se hace una vez: desde hoy, cada push se publica automáticamente.

  1. En tu repositorio, arriba, pulsa ⚙ Settings.
  2. En el menú de la izquierda, busca y pulsa Pages.
  3. En Source elige Deploy from a branch.
  4. En Branch elige main y la carpeta / (root). Pulsa Save.
  5. Espera de 1 a 3 minutos y recarga esa misma página: aparecerá el mensaje "Your site is live at…" con tu dirección.

Ese mensaje es tu certificado de que ya estás en Internet. Cópialo.

🚨 Errores frecuentes (y cómo salir de ellos)

⚠️ Si algo no se ve, casi siempre es una de estas

  • Página 404 y el repo es privado: Pages gratuito solo publica repos públicos. Ve a Settings → General → Change visibility → Public.
  • Escribiste Index.html o index.HTML: el servidor distingue mayúsculas. Renombra a index.html, todo en minúsculas.
  • La carpeta tiene espacios o tildes (Clase 01, clase única): rompe la URL. Renómbrala a clase01.
  • Editaste pero no hiciste push: revisa Source Control; si hay archivos pendientes, haz commit y Sync Changes.
  • Entregaste la URL de github.com: esa muestra el código. La de tu página termina en .github.io.
  • Acabas de activar Pages y da 404: paciencia, el primer despliegue puede tardar hasta 5 minutos. Recarga con Ctrl + F5.
  • El archivo quedó en la carpeta equivocada: en el Explorador puedes arrastrarlo a su sitio y volver a hacer commit.
