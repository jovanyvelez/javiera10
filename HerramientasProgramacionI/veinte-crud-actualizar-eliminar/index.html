🆔 Identificar elementos por ID

⏱️ 35 minutos · "Cada elemento con su nombre" — cómo encontrar un elemento exacto en el DOM

🧠 La idea central

Para editar o eliminar una tarea, primero tienes que encontrarla. En el DOM, cada elemento puede tener un id único, y JavaScript lo localiza con document.getElementById().

Es como buscar a una persona por su cédula: el id es único, así que te devuelve exactamente un elemento, no una lista.

❌ Sin id

Buscas por etiqueta o clase y obtienes muchos elementos. Tienes que filtrar manualmente cuál es el correcto.

✅ Con id

getElementById("tarea-3") te devuelve un solo elemento, directo y sin ambigüedad.

🗑️ Delete: eliminar con filter

⏱️ 35 minutos · "Adiós, tarea" — cómo quitar un elemento de un array sin romper nada

🧠 La idea central

Para eliminar una tarea, no la "borras" del array directamente. Usas filter(), que crea un nuevo array con todos los elementos excepto el que quieres quitar.

filter() recorre el array y se queda solo con los elementos que cumplen una condición. Para eliminar la tarea con id 3, te quedas con todas las que NO tienen id 3.

💻 Código de ejemplo

app.js
// Eliminar la tarea con id 3
const tareas = [
  { id: 1, titulo: "Estudiar" },
  { id: 2, titulo: "Comprar pan" },
  { id: 3, titulo: "Llamar a mamá" }
];

const nuevasTareas = tareas.filter(t => t.id !== 3);

// nuevasTareas = [ {id:1}, {id:2} ]
// La tarea 3 ya no está.

⚠️ Error común: mutar el array

No uses splice() para eliminar mientras recorres el array: cambia los índices y puedes saltarte elementos. filter() es más seguro porque no modifica el array original, crea uno nuevo.

✏️ Update: editar con find y map

⏱️ 35 minutos · "Cambiar sin romper" — cómo actualizar un elemento del array

🧠 La idea central

Para editar una tarea necesitas dos pasos: primero encontrarla con find(), y luego reemplazarla con map().

find() devuelve el primer elemento que cumple una condición. map() crea un nuevo array transformando cada elemento: si es el que quieres editar, devuelves la versión nueva; si no, lo dejas igual.

💻 Código de ejemplo

app.js
// Editar el título de la tarea con id 2
const tareas = [
  { id: 1, titulo: "Estudiar" },
  { id: 2, titulo: "Comprar pan" }
];

// 1. Encontrar la tarea
const tarea = tareas.find(t => t.id === 2);

// 2. Reemplazarla con map()
const nuevasTareas = tareas.map(t =>
  t.id === 2 ? { ...t, titulo: "Comprar pan y leche" } : t
);

// La tarea 2 ahora dice "Comprar pan y leche"

💡 Pro-Tip

El operador ... (spread) copia todas las propiedades de un objeto: { ...t, titulo: "nuevo" } crea una copia de t pero con el título cambiado. Así no pierdes el id ni las demás propiedades.

🎯 Delegación de eventos

⏱️ 35 minutos · "Un solo escuchador para todos" — cómo manejar botones que se crean dinámicamente

🧠 La idea central

Cuando creas botones de "Eliminar" o "Editar" dinámicamente (con JavaScript), no puedes ponerles un addEventListener a cada uno al crearlos... o sí, pero es frágil. La delegación de eventos es mejor: pones un solo escuchador en el contenedor, y detectas qué botón se tocó con event.target.

Es como un profesor que escucha a toda la clase: no necesita ir alumno por alumno, solo pregunta "¿quién levantó la mano?"

💻 Código de ejemplo

app.js
// Un solo escuchador en la lista
lista.addEventListener('click', (event) => {
  const boton = event.target.closest('button');

  if (boton.dataset.accion === 'eliminar') {
    eliminarTarea(boton.dataset.id);
  }
  if (boton.dataset.accion === 'editar') {
    editarTarea(boton.dataset.id);
  }
});

⚠️ Error común: escuchadores repetidos

Si pones addEventListener a cada botón al crearlo, y luego vuelves a renderizar la lista, puedes duplicar escuchadores o perderlos. Con delegación, el escuchador vive en el contenedor y siempre funciona, sin importar cuántas veces redibujes.

✅ Marcar completada y confirmar

⏱️ 35 minutos · "Los toques finales" — cambiar estado y pedir confirmación antes de borrar

🧠 La idea central

Dos detalles que hacen tu app profesional: (1) poder marcar una tarea como completada (cambiar una propiedad completada de false a true), y (2) pedir confirmación antes de eliminar, para no borrar por accidente.

Marcar completada es solo otra edición: usas map() para cambiar la propiedad. La confirmación usa confirm(), que muestra un cuadro de "Aceptar / Cancelar".

💻 Código de ejemplo

app.js
// Marcar completada
function marcarCompletada(id) {
  tareas = tareas.map(t =>
    t.id === id ? { ...t, completada: !t.completada } : t
  );
  guardar();
}

// Eliminar con confirmación
function eliminarTarea(id) {
  if (confirm('¿Seguro que quieres eliminar esta tarea?')) {
    tareas = tareas.filter(t => t.id !== id);
    guardar();
  }
}
