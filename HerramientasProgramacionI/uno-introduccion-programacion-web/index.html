🌐 ¿Qué es el desarrollo web?

⏱️ 35 minutos · "La conversación invisible" — lo que pasa cada vez que abres una página

🧠 La idea central

Imagina un restaurante. Tú (el cliente) solo quieres comer: pides la comida y te la traen. Pero detrás hay un caos organizado: alguien recibe tu pedido, alguien cocina, alguien trae el plato a la mesa, alguien cobra. Tú no ves nada de eso: solo pides y recibes.

La web es exactamente eso. Tú (el cliente) abres una página en el navegador, y en fracciones de segundo tu pedido viaja por Internet hasta un servidor (la cocina), que prepara la respuesta (el HTML, las imágenes, el video) y te la envía de vuelta para que tu navegador la "sirva" en tu pantalla.

En una frase: el desarrollo web es construir lo que el cliente pide y lo que el servidor responde.

🔄 Actividad en pareja — 2 minutos

Piensen en otro ejemplo de la vida cotidiana donde haya una "conversación invisible" entre quien pide y quien responde (por ejemplo: pedir comida a domicilio, llamar por teléfono, sacar dinero del cajero). Con su compañero/a, escojan uno y díganle al grupo: ¿quién es el cliente y quién es el servidor?

🎯 Las 3 piezas del desarrollo web

Para construir una página web se usan tres tecnologías que trabajan juntas. Memorízalas: serán la base de TODA la clase.

🏗️ HTML — Estructura

Los muros de la casa. Define qué hay en la página: títulos, párrafos, botones, imágenes, enlaces. Sin HTML no hay página.

🎨 CSS — Estilo

La pintura y la decoración. Colores, tamaños, márgenes, sombras. Hace que la página se vea bonita y ordenada en lugar de verse como un documento aburrido.

⚡ JavaScript — Comportamiento

La electricidad: le da vida. Hace que los botones funcionen, que aparezcan mensajes, que los datos se actualicen sin recargar. Sin JS la página es estática.

💡 Pro-Tip

Cuando una página "se queda cargando", lo que falla NO es tu dispositivo: es la conversación entre tu navegador y el servidor. Quizás el servidor está saturado, o el "camino" de ida y vuelta está congestionado. Por eso refrescar funciona: inicia la conversación de nuevo.

⚡ ¿Dónde está la web?

✅ Está EN todos lados

Instagram, YouTube, WhatsApp Web, Netflix, Google Docs, el portal del colegio, tu banco. Cualquier cosa que abras en un navegador o una app con conexión a Internet es desarrollo web.

La web no es solo lo que ves. Detrás de cada app hay servidores, bases de datos, APIs y lógica. El desarrollo web cubre desde el botón que tocas hasta el servidor que responde al otro lado del mundo.

🧱 Cliente y Servidor

⏱️ 35 minutos · "Las dos caras de la web" — quién pide y quién responde

🧠 La idea central

La web es una cebolla: tiene capas. En el centro está el hardware (los cables, los servidores físicos). Afuera estás tú (el usuario). Y entre medio hay varias capas de software que hacen que la conversación sea posible. El cliente y el servidor son los dos protagonistas.

El cliente no flota en el aire: vive en tu navegador (Chrome, Firefox, Edge). El servidor vive en un computador lejano, encendido 24/7, esperando peticiones. Entre los dos viaja la información por Internet.

🗺️ Las 5 capas de la web (de abajo hacia arriba)

⚡ Hardware/Cables Fibra óptica, servidores físicos en datacenters, tu router WiFi. Lo que puedes tocar.
🔧 Red/HTTP El "idioma" de la web: protocolos HTTP/HTTPS, TCP/IP. El mensajero que transporta las peticiones.
🖥️ Servidor Apache, Nginx, Node.js. El programa que escucha peticiones y prepara respuestas (HTML, JSON, imágenes).
🌐 Cliente (Navegador) Chrome, Firefox, Edge, Safari. Recibe la respuesta, interpreta HTML/CSS/JS y pinta la página en tu pantalla.
🧑 Usuario Tú. Escribes la URL, haces clic, lees, interactúas. El origen de toda petición.

⚠️ Error común

Mucha gente cree que el "servidor" es un lugar físico donde guardas archivos, como un disco duro en la nube. ¡Es solo la mitad de la historia! Un servidor es un programa que escucha peticiones y responde. Puede correr en un datacenter, en una Raspberry Pi, o incluso en tu propio computador con python3 -m http.server.

💡 HTTP: el idioma de la web

Cliente y servidor hablan un idioma llamado HTTP (HyperText Transfer Protocol). El cliente dice GET /index.html (dame esta página) y el servidor responde con el HTML. Como un mesero que anota el pedido y trae el plato. El "S" de HTTPS significa Secure: la misma conversación, pero cifrada para que nadie la espíe.

💻 Cuando un navegador le pide algo a un servidor

Las peticiones web se ven así por dentro:

request.http
// El navegador (cliente) envía esto al servidor:
GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0 (Chrome)
Accept: text/html

// El servidor responde con esto:
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1254

<!doctype html><html>...</html>

🧬 Anatomía de una página web

⏱️ 35 minutos · "HTML, CSS y JavaScript" — las 3 capas que construyen lo que ves

🧠 La idea central

Una página web no es una cosa: son tres capas que trabajan juntas. Como un sándwich: el pan de abajo (HTML), el relleno (CSS) y la cubierta (JavaScript). Cada capa hace algo distinto, y si quitas una, la página se rompe de forma diferente.

Esta misma clase interactiva que estás viendo está hecha con HTML (estructura), CSS (colores y diseño) y JavaScript (los simuladores, los quizzes, el progreso). Vamos a ver qué pasa con cada capa por separado.

💻 Así se ve el código de una mini-página

El mismo ejemplo de arriba, en código real:

index.html
<!-- HTML: la estructura -->
<h1>¡Hola, décimo! 👋</h1>
<p>Esta es una mini-página.</p>
<button id="demoBtn">🎉 Contar clics: 0</button>

/* CSS: el estilo */
<style>
  h1 { color: #22d3ee; font-size: 2rem; }
  button { background: #a855f7; color: white; }
</style>

// JavaScript: el comportamiento
<script>
  let n = 0;
  document.getElementById('demoBtn').onclick = () => {
    n++;
    document.getElementById('demoBtn').innerText = '🎉 Contar clics: ' + n;
  };
</script>

💡 Regla mnemotécnica

Para recordar las 3 capas usa esta frase: "HTML pone los ladrillos, CSS los pinta, JavaScript enciende las luces." Sin ladrillos no hay casa. Sin pintura, hay casa pero fea. Sin electricidad, hay casa bonita pero no hace nada.

🏗️ Sin HTML

No hay nada. La página está vacía. Es como una casa sin muros: no se puede habitar.

🎨 Sin CSS

El contenido sigue ahí, pero se ve como un documento plano de los 90: texto seguido, sin colores, sin márgenes. Feo pero funciona.

⚡ Sin JS

La página se ve bonita, pero no responde a nada: los botones no hacen nada, los formularios no validan, nada se actualiza sin recargar.

💡 El truco del "cargando"

Si la petición está en curso, ¿cómo es que otras pestañas siguen funcionando? Porque el navegador hace cada petición en paralelo, no una a la vez. A esto se le llama asincronía, y es una de las ideas más potentes de JavaScript: pedir algo y seguir trabajando mientras llega la respuesta.

🌍 La web está en todas partes

📱

Apps móviles

Instagram, TikTok, WhatsApp. Por dentro hablan con servidores web vía HTTP. La "app" es una carcasa sobre conversaciones web.

📺

Streaming

Netflix, YouTube, Twitch. El video llega en chunk por HTTP, pedidos uno a uno a medida que avanzas en la película.

🏦

Banca en línea

Cada transferencia es una petición HTTP firmada y cifrada (HTTPS) que va al banco y vuelve con el recibo.

🎮

Juegos multijugador

Los juegos online envían peticiones constantes al servidor: "disparé", "me moví", "enemigo muerto". Todo por la web.

⚠️ Cuando el servidor falla, ves un error

Si el servidor no responde, ves un 502 Bad Gateway o 500 Internal Server Error. Si la página no existe, ves un 404 Not Found. Esos números son códigos de estado HTTP: el idioma del servidor para decir "pasó esto". 200 = OK, 4xx = tu culpa, 5xx = culpa del servidor.
