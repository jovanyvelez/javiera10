📥 Capturar datos de formularios

⏱️ 35 minutos · "El buzón del cartero" — cómo leer lo que el usuario escribe

🧠 La idea central

Un formulario HTML (<form>) tiene campos (<input>, <textarea>, <select>) donde el usuario escribe. Pero el HTML solo dibuja los campos: no hace nada con lo que escriben. Para "leer" lo que el usuario puso, JavaScript usa la propiedad .value.

La regla es simple: cada campo tiene un id, y con document.getElementById("id").value obtienes el texto que el usuario escribió.

❌ HTML solo

El formulario se ve bonito, pero al enviar no pasa nada. Los datos se pierden: nadie los lee.

✅ HTML + JavaScript

Con .value lees cada campo y puedes guardarlo, mostrarlo o procesarlo.

📦 FormData

⏱️ 35 minutos · "El cartero que recoge todo de una vez" — capturar todos los campos juntos

🧠 La idea central

Leer campo por campo con .value funciona, pero si tu formulario tiene 10 campos, es tedioso. FormData es un objeto del navegador que recoge todos los campos de un formulario de una sola vez.

Se crea así: new FormData(formulario). Luego puedes recorrerlo con for...of o leer un campo con .get("nombre").

💻 Código de ejemplo

formdata.js
const form = document.getElementById("miFormulario");

form.addEventListener("submit", (evento) => {
  evento.preventDefault(); // evita que la página se recargue

  const datos = new FormData(form);

  // Leer un campo específico
  const nombre = datos.get("nombre");

  // Recorrer todos los campos
  for (const [clave, valor] of datos) {
    console.log(clave, "=", valor);
  }
});

⚠️ No olvides preventDefault()

Por defecto, al enviar un formulario la página se recarga y pierdes todo. Para que JavaScript tome el control, debes llamar a evento.preventDefault() dentro del evento submit. Es el error más común al empezar.

✅ Validación básica

⏱️ 35 minutos · "El filtro de calidad" — campos vacíos, longitud mínima y tipo de dato

🧠 La idea central

No puedes confiar en que el usuario llene todo bien. La validación es revisar los datos antes de usarlos. Las tres reglas básicas son:

  • Campos vacíos: ¿el usuario dejó algo en blanco?
  • Longitud mínima: ¿el texto es demasiado corto?
  • Tipo de dato: ¿es un correo válido? ¿es un número?

Si algo falla, muestras un mensaje de error y no dejas pasar el dato.

💻 Código de ejemplo

validar.js
function validar(titulo, email) {
  // 1. Campo vacío
  if (titulo === "") {
    return "El título no puede estar vacío.";
  }
  // 2. Longitud mínima
  if (titulo.length < 3) {
    return "El título debe tener al menos 3 caracteres.";
  }
  // 3. Tipo de dato (correo)
  if (!email.includes("@")) {
    return "El correo no es válido.";
  }
  return null; // null = sin errores
}

🗂️ Agregar objetos a un array

⏱️ 35 minutos · "La caja de tareas" — crear un objeto y guardarlo con push()

🧠 La idea central

Ya sabes capturar y validar. Ahora toca guardar. Cada tarea es un objeto con propiedades (título, descripción, categoría), y todas las tareas viven en un array.

El flujo es: capturar → validar → crear el objeto → agregarlo al array con push().

💻 Código de ejemplo

tareas.js
const tareas = []; // el array que guarda todo

function agregarTarea(titulo, descripcion, categoria) {
  // Crear el objeto tarea
  const tarea = {
    titulo: titulo,
    descripcion: descripcion,
    categoria: categoria
  };

  // Agregarlo al array
  tareas.push(tarea);
}

💡 Pro-Tip

push() agrega al final del array. Si quieres agregar al inicio, usa unshift(). Para quitar el último, pop(). Son las herramientas básicas de una lista.

🧹 Limpiar el formulario

Después de guardar la tarea, llama a form.reset(): borra todos los campos del formulario de una vez, sin recargar la página. Así el usuario puede escribir la siguiente tarea sin borrar a mano. El ciclo completo queda: capturar → validar → crear el objeto → push() → limpiar → renderizar.

🖼️ Renderizar la lista

⏱️ 35 minutos · "Mostrar lo guardado" — pintar el array en el HTML con innerHTML o createElement

🧠 La idea central

Guardar datos en un array no sirve de nada si el usuario no los ve. Renderizar es convertir el array en HTML visible recorriéndolo y agregando el contenido de cada tarea a la página. Hay dos caminos: construir una cadena de HTML y inyectarla con innerHTML, o crear cada elemento con createElement y agregarlo con append().

Este es el "R" de CRUD (Read): el dato sale de tu programa y se muestra.

💻 Código de ejemplo

render.js
function renderizar() {
  const lista = document.getElementById("lista-tareas");
  let html = "";

  for (const tarea of tareas) {
    html += `<li>${tarea.titulo} — ${tarea.categoria}</li>`;
  }

  lista.innerHTML = html;
}

⚠️ innerHTML reemplaza todo

Cuando asignas lista.innerHTML = html, borras lo que había y pones lo nuevo. Por eso siempre construyes el HTML completo del array, no solo el elemento nuevo. Si solo agregas, duplicarías la lista.

🧱 La otra forma: createElement + append

Construir una cadena de HTML es rápido, pero tiene un riesgo: si el texto del usuario trae etiquetas, el navegador las interpreta como HTML. La alternativa es crear cada elemento como objeto del DOM y agregarlo con append(). Es la misma técnica de la clase 15 y la que usarás en el miniproyecto de hoy:

render-createElement.js
function renderizar() {
  const lista = document.getElementById("lista-tareas");
  lista.innerHTML = ''; // vaciar la lista antes de pintar

  for (const tarea of tareas) {
    const li = document.createElement('li');
    li.textContent = tarea.titulo + ' — ' + tarea.categoria;
    lista.append(li);
  }
}

🧩 Bloque B — Escucha, valida y crea la tarea

Al enviar: preventDefault, leer .value, validar que no esté vacío (y avisar), crear el objeto tarea y agregarlo con push.

clase17-formularios/app.js — bloque B
// B. Escucha el submit, valida y crea el objeto tarea
form.addEventListener('submit', function (evento) {
  evento.preventDefault();

  const texto = campoTarea.value.trim();
  if (texto === '') {
    error.textContent = '⚠️ Escribe algo: la tarea no puede estar vacía.';
    return;
  }
  error.textContent = '';

  const tarea = { titulo: texto, categoria: campoCategoria.value, completada: false };
  tareas.push(tarea);
  form.reset();
  renderizar();
});

Ojo: renderizar() se define en el bloque C, pero como es una function, JavaScript la encuentra aunque se escriba después.

.trim() quita los espacios del inicio y del final del texto: por eso una tarea con solo espacios se considera vacía.

🧩 Bloque C — Pinta la lista sin recargar

Todo lo aprendido junto: createElement + textContent + append dentro de un for...of que recorre el array de objetos.

clase17-formularios/app.js — bloque C
// C. Pinta las tareas en el HTML sin recargar
function renderizar() {
  lista.innerHTML = '';
  for (const tarea of tareas) {
    const li = document.createElement('li');
    li.textContent = tarea.titulo + ' (' + tarea.categoria + ')';
    lista.append(li);
  }
}
