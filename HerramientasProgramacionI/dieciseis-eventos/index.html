⚡ ¿Qué es un evento?

⏱️ 35 minutos · "Algo pasa en la página" — la base de toda interactividad

🧠 La idea central

Un evento es una señal que el navegador emite cuando ocurre algo: el usuario hace clic, mueve el mouse, escribe una tecla, envía un formulario, o la página termina de cargar. JavaScript puede escuchar esos eventos y ejecutar código en respuesta.

Piensa en un timbre de casa: el evento es "alguien toca el timbre", y la respuesta es "vas a abrir la puerta". Sin el timbre (evento), nadie sabría que llegó alguien.

❌ Página sin eventos

Muestra contenido, pero no reacciona. Haces clic y no pasa nada. Es como un cartel pegado en la pared.

✅ Página con eventos

Escucha lo que haces y responde: un clic cambia un color, una tecla muestra texto, un envío valida datos.

💡 ¿Por qué importa?

Los eventos son el puente entre lo que el usuario hace y lo que tu programa responde. Sin eventos, JavaScript no tendría forma de saber cuándo actuar. Toda app interactiva —juegos, formularios, chats— está construida sobre eventos.

🖱️ addEventListener y click

⏱️ 35 minutos · "Escuchar y responder" — la función que conecta todo

🧠 La idea central

Para reaccionar a un evento usas addEventListener(). Le dices dos cosas: qué evento escuchar (por ejemplo "click") y qué función ejecutar cuando ocurra. Esa función se llama callback.

💻 La sintaxis

app.js
// 1. Seleccionas el elemento
const boton = document.querySelector('#miBoton');

// 2. Le agregas un "escuchador" de eventos
boton.addEventListener('click', function() {
  // 3. Este código se ejecuta cuando haces clic
  console.log('¡Hiciste clic!');
});

Este botón tiene un addEventListener('click', ...). Cada clic suma 1 al contador. ¡Pruébalo!

⚠️ Error común: olvidar las comillas

El nombre del evento va entre comillas: addEventListener('click', ...). Si escribes addEventListener(click, ...) sin comillas, JavaScript buscará una variable llamada click y fallará.

⌨️ input y change

⏱️ 35 minutos · "Escuchar lo que escribe el usuario" — eventos de formularios

🧠 La idea central

Los campos de texto disparan dos eventos muy útiles: input (se dispara en cada tecla, en vivo) y change (se dispara cuando el usuario termina de escribir y sale del campo). Con ellos puedes reaccionar a lo que el usuario escribe al instante.

⌨️ input

Se dispara cada vez que el valor cambia, letra por letra. Ideal para búsquedas en vivo o contadores de caracteres.

✅ change

En un campo de texto se dispara una sola vez, cuando el usuario termina y el campo pierde el foco. En checkboxes y selects, en cambio, se dispara apenas cambias el valor, sin esperar a salir del campo.

💻 Código de ejemplo

app.js
const campo = document.querySelector('#miInput');
const salida = document.querySelector('#salida');

campo.addEventListener('input', function() {
  // Se ejecuta en cada tecla
  salida.textContent = campo.value;
});

💡 Pro-Tip

Para leer lo que el usuario escribió, usa campo.value. Esa propiedad contiene el texto actual del campo. Con el evento input puedes leerlo en cada tecla y mostrarlo, contarlo o filtrarlo en vivo.

📨 submit y preventDefault

⏱️ 35 minutos · "Detener la recarga" — controlar el envío de formularios

🧠 La idea central

Cuando envías un formulario, el navegador recarga la página por defecto. Eso es un problema si quieres validar los datos o mostrar un mensaje sin perder lo escrito. El evento submit se dispara al enviar, y preventDefault() cancela ese comportamiento por defecto.

💻 La sintaxis

app.js
const formulario = document.querySelector('#miForm');

formulario.addEventListener('submit', function(evento) {
  // Cancela la recarga de la página
  evento.preventDefault();

  // Ahora puedes validar o mostrar un mensaje
  console.log('Formulario enviado sin recargar');
});

⚠️ Error común: olvidar preventDefault()

Si escuchas submit pero no llamas a evento.preventDefault(), la página se recargará y perderás todo lo que el usuario escribió. Es el paso más olvidado al trabajar con formularios.

🌐 Delegación de eventos

⏱️ 35 minutos · "Un solo escuchador para muchos" — eficiencia con elementos dinámicos

🧠 La idea central

Imagina una lista con 100 botones. ¿Pones 100 addEventListener? No. La delegación de eventos consiste en poner un solo escuchador en el contenedor padre, y detectar cuál elemento hijo fue el que disparó el evento usando evento.target.

Es especialmente útil con botones dinámicos: elementos que se crean después de cargar la página. Un escuchador en el padre los captura a todos, incluso a los nuevos.

💻 La sintaxis

app.js
const lista = document.querySelector('#lista');

// Un solo escuchador en el padre
lista.addEventListener('click', function(evento) {
  // evento.target es el elemento que realmente se clicó
  if (evento.target.tagName === 'BUTTON') {
    console.log('Clic en:', evento.target.textContent);
  }
});

🎮 Simulador: Botones dinámicos

Haz clic en "Agregar botón" para crear botones nuevos. Luego haz clic en ellos: un solo escuchador en el contenedor los captura a todos, incluso a los recién creados.

🌐 Delegación — botones dinámicos

👁️ Observa

Cada botón nuevo es capturado por el mismo escuchador del contenedor.

💡 Pro-Tip

La clave es evento.target: te dice exactamente qué elemento disparó el evento. Con eso, un solo escuchador en el padre puede manejar cientos de hijos, presentes y futuros.

🧩 Bloque A — El botón que cuenta (evento click)

addEventListener escucha el clic; textContent actualiza el número.

🧩 Bloque B — El input que repite en vivo (evento input)

El evento input se dispara en cada tecla: la página reacciona mientras escribes.

clase16-eventos/app.js — bloque B
// B. El input que repite en vivo (evento input)
const campo = document.getElementById('campo-eco');
const eco = document.getElementById('eco');

campo.addEventListener('input', function () {
  eco.textContent = 'Tú escribes: ' + campo.value;
});

🧩 Bloque C — El formulario que NO recarga (submit + preventDefault)

El evento submit dispara el envío; el objeto evento llega como parámetro y preventDefault() cancela la recarga.

clase16-eventos/app.js — bloque C
// C. El formulario que NO recarga la página
const form = document.getElementById('form-prueba');
const mensaje = document.getElementById('mensaje-form');

form.addEventListener('submit', function (evento) {
  evento.preventDefault();
  mensaje.textContent = 'Enviaste: ' + document.getElementById('campo-form').value + ' — ¡y la página no recargó!';
});

🧩 Bloque D — El interruptor que muestra y oculta (evento change)

El checkbox dispara change al cambiar de estado, y classList.toggle() prende o apaga la clase oculto.

clase16-eventos/app.js — bloque D
// D. El interruptor que muestra y oculta (evento change)
const chk = document.getElementById('chk-secreto');
const secreto = document.getElementById('secreto');

chk.addEventListener('change', function () {
  secreto.classList.toggle('oculto');
});
