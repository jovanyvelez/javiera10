💾 ¿Qué es localStorage?

⏱️ 35 minutos · "La memoria que no se olvida" — por qué los datos desaparecen y cómo evitarlo

🧠 La idea central

Cuando declaras una variable en JavaScript, vive en la memoria RAM del navegador. Si recargas la página o cierras la pestaña, esa memoria se limpia y todo se pierde. El localStorage es un almacén persistente: guarda datos en el disco del navegador, y siguen ahí aunque cierres todo y vuelvas mañana.

Es como la diferencia entre escribir en una pizarra (se borra) y escribir en un cuaderno (se conserva).

🧠 Memoria (variables)

Vive en la RAM. Rápida, pero volátil: se borra al recargar o cerrar la página. Ideal para datos temporales.

💾 Almacenamiento persistente

Vive en el disco del navegador. Sobrevive a recargas y cierres. Ideal para preferencias, tareas, puntajes.

💡 ¿Dónde vive localStorage?

El localStorage es un objeto global de JavaScript que guarda pares clave → valor como texto. Cada sitio web tiene su propio almacén: lo que guardas en una página no lo ve otra. Y se conserva por origen (dominio), no por pestaña.

📥 setItem y getItem

⏱️ 35 minutos · "Guardar y leer" — las dos funciones que usarás siempre

🧠 La idea central

Para guardar algo usas localStorage.setItem(clave, valor) y para leerlo localStorage.getItem(clave). La clave es un nombre que tú eliges (como una etiqueta), y el valor siempre se guarda como texto.

📥 Las dos funciones básicas

FunciónQué haceEjemplo
setItem(clave, valor)Guarda (o sobrescribe) un valor bajo una clavelocalStorage.setItem("nombre", "Javiera")
getItem(clave)Lee el valor guardado; devuelve null si no existelocalStorage.getItem("nombre")

💻 Código de ejemplo

app.js
// Guardar una tarea
localStorage.setItem("tarea", "Hacer la tarea de matemáticas");

// Leerla de vuelta
const tarea = localStorage.getItem("tarea");
console.log(tarea); // "Hacer la tarea de matemáticas"

// Si la clave no existe, devuelve null
const inexistente = localStorage.getItem("no-existe");
console.log(inexistente); // null

⚠️ Error común: olvidar que todo es texto

Si guardas un número con setItem("edad", 15), al leerlo con getItem recibirás el texto "15", no el número 15. Para operaciones matemáticas tendrás que convertirlo (por ejemplo con Number()).

🧩 JSON.stringify y JSON.parse

⏱️ 35 minutos · "Objetos a texto y de vuelta" — guardar estructuras completas

🧠 La idea central

localStorage solo guarda texto. Pero tú quieres guardar un array de objetos (una lista de tareas, por ejemplo). Ahí entra JSON: un formato de texto que representa datos estructurados. JSON.stringify() convierte un objeto en texto, y JSON.parse() convierte ese texto de vuelta en objeto.

📦 JSON.stringify(objeto)

Convierte un objeto o array en una cadena de texto JSON, lista para guardar en localStorage.

JSON.stringify({ nombre: "Javiera", edad: 15 }) // → '{"nombre":"Javiera","edad":15}'

📤 JSON.parse(texto)

Convierte una cadena JSON de vuelta en un objeto o array utilizable en JavaScript.

JSON.parse('{"nombre":"Javiera","edad":15}') // → { nombre: "Javiera", edad: 15 }

💻 Guardar un array de objetos

app.js
// Un array de objetos (tareas)
const tareas = [
  { id: 1, texto: "Estudiar", hecha: false },
  { id: 2, texto: "Practicar", hecha: true }
];

// Guardar: convertir a texto y guardar
localStorage.setItem("tareas", JSON.stringify(tareas));

// Leer: recuperar el texto y convertirlo de vuelta
const guardadas = JSON.parse(localStorage.getItem("tareas"));
console.log(guardadas[0].texto); // "Estudiar"

💡 Pro-Tip

El patrón JSON.stringify al guardar y JSON.parse al leer es el más usado de la web para persistir datos. Lo verás en casi toda app que guarde listas, configuraciones o puntajes en el navegador.

🗑️ removeItem y clear

⏱️ 35 minutos · "Borrar con cuidado" — eliminar un dato o todo el almacén

🧠 La idea central

Así como guardas y lees, también necesitas borrar. removeItem(clave) elimina una sola clave, y clear() vacía todo el almacén del sitio. Ojo: clear() no pide confirmación, así que úsalo con cuidado.

🗑️ Las dos funciones de borrado

FunciónQué haceEjemplo
removeItem(clave)Elimina solo la clave indicadalocalStorage.removeItem("tarea")
clear()Vacía todo el almacén del sitiolocalStorage.clear()

⚠️ clear() no pide permiso

localStorage.clear() borra todas las claves de tu sitio de una sola vez, sin confirmación. En una app real, casi siempre preferirás removeItem para borrar solo lo que necesitas, y reservar clear para un botón de "borrar todo" bien señalizado.

🔒 Limitaciones y seguridad

⏱️ 35 minutos · "Conocer los límites" — qué sí y qué no guardar en localStorage

🧠 La idea central

localStorage es genial, pero no es una base de datos. Tiene límites de tamaño, solo guarda texto, y —lo más importante— no es seguro para datos sensibles. Saber qué guardar y qué no es parte de ser un buen desarrollador.

🔒 Las 4 limitaciones clave

LimitaciónQué significa
1. Tamaño limitadoUnos 5–10 MB por sitio. No sirve para archivos grandes.
2. Solo textoGuarda cadenas; para objetos necesitas JSON.
3. Solo en ese navegadorNo se sincroniza entre dispositivos ni navegadores.
4. No es seguroCualquier script de la página puede leerlo. No guardes secretos.

🚫 Nunca guardes datos sensibles

Contraseñas, números de tarjeta, tokens de sesión o datos personales delicados no deben ir en localStorage. Cualquier código JavaScript que corra en la página (incluido un script malicioso) puede leerlos. Para eso existen soluciones seguras del lado del servidor.

💡 ¿Qué SÍ guardar?

Preferencias de tema (claro/oscuro), tareas de una lista, puntajes de un juego, borradores de texto, configuraciones de la app. Datos no sensibles que mejoran la experiencia sin riesgo.
