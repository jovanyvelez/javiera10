📚 ¿Qué es CRUD?

⏱️ 35 minutos · "Las cuatro operaciones de toda app" — Create, Read, Update, Delete

🧠 La idea central

CRUD es un acrónimo de las cuatro operaciones básicas que hace casi cualquier aplicación con sus datos: Create (crear), Read (leer), Update (actualizar) y Delete (borrar).

Piensa en tu lista de contactos del celular: puedes agregar un contacto (Create), ver la lista (Read), editar un número (Update) y eliminar a alguien (Delete). Esas cuatro acciones son el CRUD.

🏗️ Arquitectura: datos, almacenamiento y renderizado

⏱️ 35 minutos · "Tres piezas que trabajan juntas" — el patrón de toda app con datos

🧠 La idea central

Toda app que maneja datos tiene tres piezas que se repiten una y otra vez: los datos (un array en memoria), el almacenamiento (localStorage, para que sobrevivan a la recarga) y el renderizado (pintar esos datos en la pantalla).

📦 1. Datos

Un array de objetos en memoria. Cada tarea es un objeto con id y texto. Es la "fuente de la verdad".

💾 2. Almacenamiento

localStorage guarda los datos como texto. Así, al recargar la página, la información no se pierde.

🖥️ 3. Renderizado

Una función que lee el array y dibuja cada tarea en el HTML. Si el array cambia, la pantalla cambia.

🔁 El ciclo de vida

PasoQué pasaFunción
1. CargarAl abrir la app, lee lo guardadocargarTareas()
2. RenderizarPinta las tareas en pantallarenderizarTareas()
3. CrearEl usuario agrega una tareaagregarTarea()
4. GuardarSe escribe en localStorageguardarTareas()
5. RenderizarSe vuelve a pintar la listarenderizarTareas()

⚠️ Error común: olvidar renderizar

Si agregas una tarea al array pero no vuelves a llamar a renderizarTareas(), la pantalla no cambia. El dato está en memoria, pero el usuario no lo ve. Regla de oro: cada vez que cambian los datos, renderiza de nuevo.

🆔 Generar IDs únicos

⏱️ 35 minutos · "Cada tarea necesita su cédula" — Date.now() y crypto.randomUUID()

🧠 La idea central

Cuando creas muchas tareas, necesitas distinguirlas. Para eso cada tarea lleva un id: un valor único que la identifica. Hay dos formas comunes de generarlo en JavaScript: Date.now() y crypto.randomUUID().

⏱️ Date.now()

Devuelve los milisegundos transcurridos desde 1970. Es un número grande y casi siempre único. Simple y rápido.

const id = Date.now();
// 1720000000000

🔐 crypto.randomUUID()

Genera un identificador universal (UUID) con letras y números. Prácticamente imposible que se repita.

const id = crypto.randomUUID();
// "a1b2c3d4-..."

➕ Create: la función agregarTarea

⏱️ 35 minutos · "Manos a la obra" — crear tareas y guardarlas automáticamente

🎯 La misión

Vas a construir la C de CRUD: una función agregarTarea() que toma lo que escribe el usuario, le pone un id, lo agrega al array, lo guarda en localStorage y lo muestra en pantalla.

💻 La función agregarTarea

app.js
let tareas = [];

function agregarTarea(texto) {
  const tarea = {
    id: Date.now(),
    texto: texto
  };
  tareas.push(tarea);
  guardarTareas();
  renderizarTareas();
}

📖 Read: cargarTareas y renderizarTareas

⏱️ 35 minutos · "Leer lo guardado" — traer datos de localStorage y pintarlos

🧠 La idea central

La R de CRUD tiene dos funciones: cargarTareas() lee los datos de localStorage al abrir la app, y renderizarTareas() los dibuja en la pantalla. Juntas hacen que lo guardado "vuelva a la vida".

💻 Las dos funciones de Read

app.js
function cargarTareas() {
  const datos = JSON.parse(localStorage.getItem('tareas'));
  tareas = datos || [];
}

function renderizarTareas() {
  const lista = document.getElementById('lista');
  lista.innerHTML = '';
  tareas.forEach(tarea => {
    const item = document.createElement('li');
    item.textContent = tarea.texto;
    lista.appendChild(item);
  });
}

💡 JSON.parse y JSON.stringify

localStorage solo guarda texto. Por eso, al guardar usas JSON.stringify() (convierte el array a texto) y al leer usas JSON.parse() (convierte el texto de vuelta a array). Son la pareja inseparable de la persistencia.
