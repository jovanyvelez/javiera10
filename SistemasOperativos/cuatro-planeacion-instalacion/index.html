🧭 ¿Qué es la planificación?

⏱️ 35 minutos · "Antes de clavar, medir dos veces" — por qué planificar

🧠 La idea central

Instalar un SO no es meter una USB y darle "siguiente, siguiente, siguiente". Si haces eso sin planear, puedes perder tus archivos, elegir un SO que no corre en tu PC, o quedar con un equipo que no arranca. La planificación es el paso anterior a la instalación: pensar qué vas a instalar, dónde y cómo, antes de tocar una sola tecla.

Como en cocina: antes de cocinar revisas la receta, los ingredientes y los utensilios. Aquí igual: antes de instalar revisas requisitos, espacio y herramientas.

🔄 Actividad en pareja — 2 minutos

Piensen en una vez que instalaron algo (una app, un juego, algo en el celular) y salió mal porque no leyeron los requisitos o no respaldaron nada. Cuéntenlo. Ese "salió mal" es exactamente lo que evita la planificación.

🎯 Los 3 objetivos de la planificación

Planificar persigue tres metas claras. Memorízalas: son la base de todo.

✅ Elegir bien

Decidir el SO correcto para el hardware y el uso. No es lo mismo un SO para un servidor que para una laptop vieja o para tu celular.

💾 No perder datos

Revisar qué hay en el disco, respaldar lo importante y organizar las particiones para no borrar lo que sí importa.

🛡️ Que todo arranque

Preparar el medio (USB/ISO), la BIOS/UEFI y el bootloader para que, al terminar, el equipo encienda y arranque sin sorpresas.

📋 Las características de una buena planificación

Una planificación bien hecha tiene estas características. Si falta una, el plan es incompleto.

🧩 Características de la planificación

Toca cada tarjeta para descubrir qué significa. Hay 5 características clave.

💡 Pro-Tip

En el mundo profesional, antes de instalar en producción se hace una prueba en un entorno virtual (como VirtualBox). Si algo falla, falla en la virtual y no en tu máquina real. Por eso en este curso usaremos VirtualBox para los talleres.

💻 La planificación en una terminal real

Antes de instalar, un administrador revisa el hardware con comandos. Así se ve en Linux:

terminal — pre-install
$ lscpu            # ¿qué procesador tengo?
$ free -h          # ¿cuánta RAM?
$ lsblk            # ¿qué discos y particiones hay?
$ df -h            # ¿cuánto espacio libre queda?
$ sudo dmidecode -t bios  # ¿BIOS o UEFI?

⚡ ¿Por qué NO planificar sale caro?

❌ Instalas sin espacio

El instalador avanza hasta el 70% y luego dice "no hay espacio". Todo ese tiempo perdido. Peor: puede dejar el disco a media partición y el equipo no arranca.

✅ Planificas antes

Revisas lsblk, ves que faltan 20 GB, liberas o agregas disco, y luego la instalación avanza limpia hasta el 100%. Sin sorpresas.

⚠️ Error común

Mucha gente instala Windows 11 en una laptop vieja porque "es el más nuevo". Resultado: la laptop va lentísima porque Windows 11 pide 4 GB de RAM mínimo y TPM 2.0. El más nuevo no es siempre el mejor para tu hardware. A veces un Linux ligero (como Lubuntu o Xubuntu) corre mejor en equipos viejos.

💡 El criterio "costo" no es solo dinero

Linux es gratis y libre. Windows y macOS cuestan dinero (o vienen "incluidos" en el equipo). Pero el costo también incluye soporte, apps disponibles, curva de aprendizaje y hardware compatible. Un SO gratis que no corre tu app favorita puede salir más caro que uno de pago que sí la corre.

🧱 Preparación del equipo

⏱️ 40 minutos · "El disco, el medio y la BIOS" — los 3 preparativos

🧠 La idea central

Antes de instalar, hay que preparar 3 cosas: el disco (particiones), el medio de instalación (USB booteable con la ISO) y el firmware (BIOS/UEFI). Si falla cualquiera de los tres, la instalación no arranca o pierde datos. Vamos a ver cada uno.

🗄️ 1. Particiones de disco

Un disco se puede dividir en particiones: trozos lógicos que el SO ve como discos separados (C:, D:, /dev/sda1…). Planificar las particiones es decidir cuántas y para qué.

📦 Partición del sistema

Donde vive el SO. En Windows suele ser la C:. En Linux, / (root). Aquí van los archivos del sistema operativo.

📂 Partición de datos

Para tus archivos, separada del sistema. Si el SO se daña, tus datos siguen ahí. En Windows: D:. En Linux: /home.

🔧 Partición especial

Para arranque (/boot o EFI), recuperación o swap (memoria de intercambio en disco). Sin estas, el SO no arranca o no hiberna.

⚠️ ¡Cuidado con formatear!

Formatear una partición borra todo lo que tiene. Por eso, antes de instalar, identificas qué partición tiene tus datos y la no tocas. El instalador te preguntará dónde instalar; si dudas, detente y revisa.

💽 2. Medio de instalación: la ISO y la USB booteable

Una ISO es una imagen del disco de instalación: un archivo que contiene todo lo necesario para instalar el SO. Hoy casi nadie usa CDs: se graba la ISO en una USB booteable con herramientas como Rufus (Windows) o dd / balenaEtcher (Linux/macOS).

crear-usb.sh
# 1. Descargar la ISO oficial (ej. Ubuntu 24.04)
# 2. Insertar la USB y ver cómo se llama (¡cuidado!)
$ lsblk                  # ver el dispositivo, ej. /dev/sdb

# 3. Grabar la ISO en la USB (linux/mac):
$ sudo dd if=ubuntu-24.04.iso of=/dev/sdb bs=4M status=progress
$ sync

# En Windows: usar Rufus o balenaEtcher (modo gráfico)

⚠️ ¡OJO con dd!

El comando dd copia byte a byte. Si te equivocas de dispositivo (of=/dev/sda en vez de /dev/sdb) borras tu disco principal entero. Por eso siempre se revisa con lsblk antes. Mide dos veces, corta una.

🔧 3. BIOS o UEFI: el firmware que decide de dónde arrancar

Antes de que el SO cargue, un pequeño programa ya corrió: el firmware. Hay dos familias:

🕹️ BIOS (Legacy)

El firmware clásico (años 80). Pantalla azul, solo teclado. Arranca en modo Legacy, particiones MBR (hasta 2 TB, 4 particiones primarias). Hoy casi obsoleto.

⚡ UEFI

El sucesor moderno. Soporta ratón, gráficos, arranque rápido, particiones GPT (discos grandes), Secure Boot (verifica firma del SO). Lo usan todos los PCs desde ~2012.

💡 ¿Cómo entro a la BIOS/UEFI?

Al encender el PC, antes de que cargue Windows/Linux, presionas una tecla repetidamente: F2, F10, Supr o Esc (depende del fabricante). Allí cambias el boot order para que la USB arranque primero. Sin esto, el PC ignora la USB y arranca el SO viejo.

🚀 El arranque del SO

⏱️ 35 minutos · "Del botón de power al escritorio" — la secuencia de boot

🧠 La idea central

Cuando presionas el botón de encendido, no arranca el SO directamente. Hay una secuencia de boot: el firmware, el bootloader y luego el SO. Entender esta cadena es entender por qué a veces "no arranca" y cómo se arregla.

💡 ¿Qué es GRUB?

GRUB (GRand Unified Bootloader) es el bootloader más usado en Linux. Aparece como un menú al arrancar: elige qué SO cargar si tienes varios (dual-boot). En Windows el equivalente es el Windows Boot Manager. El bootloader es el "menú del desayuno" del equipo: decide qué SO se sirve.

🌍 Tipos de arranque

🥶

Arranque en frío

El equipo estaba apagado totalmente. El firmware hace POST (autodiagnóstico) completo antes de buscar el SO. Más lento, más seguro.

🔄

Reinicio / warm boot

El equipo ya estaba encendido. Se salta parte del POST y reinicia más rápido. Es el "Reiniciar" del menú.

💤

Hibernación / sleep

El estado del SO se guardó en disco (hibernar) o en RAM (suspender). Al despertar, se salta casi todo el boot y vuelve donde estabas.

🌐

Arranque por red (PXE)

En servidores y aulas: el equipo no tiene disco y descarga el SO por red desde un servidor. Se usa en laboratorios escolares.

⚠️ Cuando el bootloader falla

Si el bootloader se daña, enciendes y ves un mensaje como GRUB rescue> o No bootable device. El equipo funciona, pero no sabe cómo cargar el SO. Se arregla reinstalando el bootloader desde una USB live. Por eso siempre conviene tener una USB booteable a mano. 🚨

💡 Dual-boot: dos SO en una sola PC

Con dual-boot tienes dos SO en el mismo disco (por ejemplo Windows + Linux). Al encender, el bootloader te pregunta cuál cargar. Es ideal para probar Linux sin renunciar a Windows. Ojo: instala Windows primero, luego Linux, porque el bootloader de Windows sobrescribe el de Linux y rompe el menú.
