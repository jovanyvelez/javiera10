🧭 ¿Qué es un Sistema Operativo?

⏱️ 35 minutos · "El director de orquesta" — el intermediario entre tú y la máquina

🧠 La idea central

Imagina un restaurante. Tú (el cliente) solo quieres comer: pides la comida y te la traen. Pero detrás hay un caos organizado: alguien asigna las mesas, alguien cocina, alguien cobra, alguien limpia. Ese "alguien" que coordina todo sin que tú te enteres… es el gerente del restaurante.

Un Sistema Operativo (SO) es exactamente eso: el gerente del computador. Es un programa especial que se encarga de que todo funcione —la pantalla, el teclado, los archivos, los programas— y que traduce tus deseos ("abrir esta foto") en órdenes que el hardware entiende ("enciende estos pixeles, lee estos bytes del disco").

En una frase: el SO es el intermediario entre el usuario y el hardware.

🔄 Actividad en pareja — 2 minutos

Piensen en otro ejemplo de la vida cotidiana donde haya un "intermediario invisible" (por ejemplo: el director de un coro, un traductor en una reunión, un recepcionista en un hotel). Con su compañero/a, escojan uno y díganle al grupo: ¿qué pasaría si ese intermediario desapareciera?

🎯 Las 4 grandes tareas del SO

El "gerente" tiene cuatro responsabilidades enormes. Memorízalas: serán la base de TODA la clase.

🧠 Procesador (CPU)

Decide qué programa usa el cerebro del computador y cuándo. Como un maître que asigna las mesas: nadie se queda sin atención, todos parecen atendidos a la vez.

💾 Memoria (RAM)

Reparte la "mesa de trabajo" entre los programas. Si 10 apps quieren memoria al mismo tiempo, el SO decide qué cacho le toca a cada una sin que se pisen.

🗄️ Almacenamiento

Organiza los archivos en el disco (fotos, apps, documentos). Es el archivador: sabe dónde está cada cosa aunque haga meses que no la abres.

🔌 Dispositivos (I/O)

Habla con teclado, pantalla, impresora, red, Bluetooth, cámara… Es el traductor universal: convierte "tocaste la pantalla" en coordenadas, "presionaste una tecla" en una letra, "llegó un WiFi" en una página web.

🎮 Simulador: El Restaurante del SO

Tú eres el gerente. Cada vez que llega un cliente, el SO (tú) le asigna una mesa (CPU), pide a la cocina su pedido (memoria) y registra el ingreso. Observa cómo todo se coordina sin que el cliente vea el caos.

💡 Pro-Tip

Cuando tu celular "se cuelga", lo que falla NO es la app: es el SO que no logra repartir la CPU o la RAM entre tantas apps. Por eso reiniciar funciona: el SO empieza de cero y vuelve a coordinar todo.

⚡ ¿Dónde está el SO?

✅ Está EN todos lados

Celular, laptop, tablet, smart TV, consola de videojuegos, reloj inteligente, router WiFi, cajero automático, el sistema del auto, una nave espacial. Si tiene chip y pantalla, tiene SO.

❌ NO es una app

El SO no es WhatsApp ni Chrome. Es lo que permite que WhatsApp y Chrome existan. Es la capa de abajo: sin SO, ningún programa podría arrancar.

🧱 Anatomía por capas

⏱️ 35 minutos · "La cebolla del computador" — dónde vive el SO

🧠 La idea central

Un computador es como una cebolla: tiene capas. En el centro está el hardware (los chips, los cables). Afuera estás tú (el usuario). Y entre medio… están varias capas de software, siendo el SO la más importante.

El SO no flota en el aire: vive justo encima del hardware y debajo de las aplicaciones. Es el puente.

🗺️ Las 5 capas (de abajo hacia arriba)

⚡ Hardware Chips, circuitos, disco, pantalla física. Lo que puedes tocar.
🔬 Kernel El corazón del SO. Habla directamente con el hardware. Nadie lo ve.
🖥️ Sistema Operativo Windows, Linux, Android… Los servicios: archivos, red, permisos, ventanas.
📱 Aplicaciones WhatsApp, Chrome, juegos, el editor de fotos. Lo que tú usas.
🧑 Usuario Tú. Das las órdenes tocando, escribiendo, hablando.

⚠️ Error común

Mucha gente cree que el navegador (Chrome) es el sistema operativo. ¡Falso! Chrome es una aplicación que corre encima del SO. Si tu SO es Linux, Chrome corre sobre Linux; si es Windows, corre sobre Windows.

💡 El kernel: el jefe que nadie ve

Dentro del SO hay un núcleo llamado kernel. Es el único programa con permiso para tocar el hardware directamente. Las apps nunca tocan el hardware: le piden al kernel, y él decide. Es como el jefe de cocina que es el único que puede entrar a la cocina: los meseros piden, pero no entran.

💻 Cuando una app le pide algo al SO

Las apps hablan con el SO mediante "llamadas al sistema" (syscalls). Así se ve en código:

app.cs
// La app QUIERE abrir un archivo...
File.Open("foto.jpg");

// ...pero en realidad le pide al kernel:
syscall("open", "foto.jpg");
// el kernel verifica permisos y abre el archivo

📜 Historia y evolución

⏱️ 35 minutos · "De tarjetas perforadas a tu bolsillo" — 70 años en 7saltos

🧠 La idea central

El SO no apareció de la nada: evolucionó. Al principio no existía (tú mismo conectabas los cables). Luego se automatizó, se hizo portátil, llegó a tu casa y finalmente a tu bolsillo. Cada salto resolvió un problema del anterior.

🔄 Actividad en pareja — 2 minutos

Antes de leer la línea de tiempo: con su compañero/a, adivinen. ¿En qué década creen que apareció el primer SO que se parece a los de hoy? (con ventanas, íconos, ratón). Apúntelo mentalmente y luego revisen.

🕰️ Línea de tiempo interactiva

Toca cada era para descubrir qué cambió. Observa cómo cada salto resolvió un problema del anterior.

⏪
Años 50 · Sin SO
El operador humano era el SO

Las primeras computadoras (ENIAC, UNIVAC) no tenían SO. El programador conectaba cables físicamente y usaba tarjetas perforadas para dar las instrucciones. Cada turno duraba horas. Si algo fallaba, empezabas de cero.

🔥 Cambió: apareció la idea de "automatizar" la operación.
①
Años 60 · Batch
Procesamiento por lotes

Nace el primer SO real: en lugar de una tarjeta a la vez, se apilaban muchas (un "lote" o batch) y una rutina las procesaba una tras otra sin intervención humana. IBM lanza OS/360 en 1964. La gente ya no esperaba entre trabajos.

🔥 Cambió: el computador dejó de esperar al humano.
②
Años 70 · Multiprogramación
Unix y el tiempo compartido

Varios programas podían estar en memoria a la vez y el SO les daba turnitos de CPU tan rápidos que parecían simultáneos. Aparece Unix (1969, Ken Thompson & Dennis Ritchie en Bell Labs) y con él el lenguaje C. Unix es el abuelo de Linux, macOS y Android.

🔥 Cambió: varios usuarios al mismo tiempo, en la misma máquina.
③
Años 80 · PC + GUI
El SO llega a casa, con ventanas

Las computadoras personales llegan al hogar. MS-DOS (Microsoft, 1981) se instala en el IBM PC: era de línea de comandos. Luego Xerox PARC inventa la interfaz gráfica (ventanas, íconos, ratón) y Apple la populariza con el Macintosh (1984). Adiós a escribir comandos: ahora tocas íconos.

🔥 Cambió: el SO se volvió usable para no-programadores.
④
Años 90 · Windows 95 + Linux
El SO dominante y el SO libre

Windows 95 lleva la GUI a casi todo el planeta. Pero en 1991, un estudiante finlandés llamado Linus Torvalds crea Linux y lo libera gratis con su código fuente abierto. Hoy Linux corre en el 90% de los servidores de Internet, en todo Android y en la Estación Espacial Internacional.

🔥 Cambió: nació el software libre y la colaboración mundial.
⑤
Años 2000 · Móvil
El SO se va al bolsillo

Llegan los smartphones. iOS (Apple, 2007) y Android (Google, 2008, basado en Linux) hacen que cada persona lleve un SO en el bolsillo. El SO ahora debe administrar batería, sensores, GPS, táctil. Ya no es solo para escritorio: es para caminar.

🔥 Cambió: el SO aprendió a ahorrar energía y a ir contigo.
⑥
Años 2010-2025 · Cloud + IA
El SO en la nube y en todas partes

El SO ya no vive solo en tu aparato: vive en la nube (centros de datos con miles de máquinas). Aparecen los asistentes de voz, los SO de autos autónomos, los SO de relojes, routers, TVs, cajeros. Y ahora la IA empieza a integrarse dentro del SO (Windows Copilot, Android Gemini). El intermediario cada vez es más inteligente.

🔥 Cambió: el SO está en cada objeto con chip, y empieza a "entender" tu intención.

📖 Dato curioso

El nombre "Windows" viene de las "ventanas" en pantalla que puedes abrir y cerrar. Antes de Windows 95, para copiar un archivo escribías copy archivo.txt destino/. Después, lo arrastras con el ratón. Misma tarea, dos mundos distintos.

🌳 Familias de SO hoy

⏱️ 35 minutos · "El árbol genealógico" — de quién desciende cada SO

🧠 La idea central

Hoy existen decenas de sistemas operativos, pero casi todos descienden de cuatro familias. Como en genealogía: hay troncos comunes y ramas. Conocer el árbol te ayuda a entender por qué unos son parecidos entre sí y otros no.

🌲 El árbol genealógico

Unix (1969) — el tronco común

🪟 Windows

De Microsoft. Nació como capa gráfica sobre MS-DOS. Hoy es la familia más usada en PCs de escritorio.

Windows 10Windows 11Windows Server

🍎 macOS

De Apple. Desciende de Unix (vía BSD). Privativo, pero por dentro es primo de Linux. Muy pulido.

🐧 Linux

Libre y gratuito. Desciende de Unix. Mueve servidores, Android, routers, coches. Abierto: cualquiera puede ver y modificar su código.

📱 Móviles

Hoy casi todo móvil usa Android (Linux) o iOS (Unix). Las dos grandes familias comparten tronco.

💡 ¿Por qué Linux importa tanto?

Linux es open source (código abierto): su código es público y cualquiera puede leerlo, modificarlo y redistribuirlo. Por eso se adaptó a miles de usos: desde tu Android hasta el supercomputador que predice el clima. Es libre como el aire, y por eso está en todas partes.

💻 Familias en la terminal

Las familias Unix (Linux, macOS) comparten comandos. Windows no. Por eso en macOS funciona ls pero en Windows usas dir:

comparativa
# Linux / macOS (familia Unix):
$ ls              # listar archivos
$ cp a.txt b.txt  # copiar
$ rm a.txt        # borrar

# Windows (familia propia):
> dir             # listar archivos
> copy a.txt b.txt # copiar
> del a.txt       # borrar

🕵️ El intermediario invisible

⏱️ 35 minutos · "Lo que pasa cuando tocas un ícono" — el SO en acción

🧠 La idea central

Cuando tocas el ícono de una app en tu celular, parece magia: la app abre. Pero en realidad acaba de ocurrir una cadena de pasos que involucra al usuario, la app, el SO, el kernel y el hardware. El SO es el intermediario invisible que conecta todo. Entender esa cadena es entender qué es un SO de verdad.

💡 El truco de la "simultaneidad"

Si el SO está atendiendo una petición, ¿cómo es que otras apps siguen funcionando? Porque el kernel reparte la CPU en turnitos de milisegundos, tan rápido que parece simultáneo. A esto se le llama multitarea, y es la magia que inventó Unix en los 70.

🌍 El SO está en todas partes

🚗

Auto moderno

El sistema de infoentretenimiento, los frenos ABS y hasta el control de crucero corren sobre un SO (muchas veces Linux).

🏦

Cajero automático

Cada cajero tiene un SO que gestiona pantalla, lector de tarjetas y contador de billetes. Muchos aún usan Windows XP embebido.

🛰️

Satélites y naves

El rover de Marte, la Estación Espacial y los satélites usan SO de tiempo real (y Linux en muchos casos).

📺

Smart TV

La TV que navega Netflix tiene un SO dentro (Tizen, webOS, Android TV). Mismo intermediario, otra pantalla.

⚠️ Cuando el SO falla, falla todo

Si una app se cuelga, la cierras y listo. Pero si el SO se cuelga, todo el aparato se reinicia (pantallazo azul, kernel panic). Por eso el SO es el programa más cuidado y testeado del computador: si él cae, todo cae.
